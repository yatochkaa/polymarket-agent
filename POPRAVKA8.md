## 1. Предмет

Правило исключения рынков, для которых предматчевая полнота ленты
сделок недоказуема. Поправка принимается ДО первого прогона сбора
и до просмотра любых CLV.

## 2. Установленные факты об эндпоинте data-api.polymarket.com/trades

Измерено пробником probes/diag_trades_depth.py:

- Параметр limit насыщается на 10000. Запросы limit=20000, 30000,
  50000 возвращают ровно 10000 строк.
- Параметр offset ограничен сверху значением 10000. offset=11000 и
  offset=20000 возвращают HTTP 400. Ограничение действует и для
  ?user=, и для ?market=.
- Следовательно максимальная достижимая глубина по одному рынку —
  20000 последних сделок.
- Порядок выдачи всегда убывающий по времени. Шесть вариантов
  параметров сортировки (ascending=true, order=timestamp,
  order=timestamp&ascending=true, sortDirection=ASC,
  sort=timestamp&dir=asc) дали идентичный убывающий порядок.
  Неизвестные параметры эндпоинт игнорирует молча.
- Ранее зафиксированный максимум 10500 сделок был артефактом
  пагинации с limit=500 (10000 + последняя страница 500), а не
  реальным потолком.

## 3. Следствие для предматчевой полноты

Лента отдаётся от новых сделок к старым. Недостижим всегда самый
СТАРЫЙ хвост. Отсюда:

- Эталонная цена p_ref (последняя сделка строго до gameStartTime,
  §2 Поправки 7) лежит вблизи конца предматчевого периода и
  достижима всегда.
- Множество кошельков и цена входа VWAP (§3 Поправки 7) требуют
  ВСЕХ сделок кошелька по матчу. При обрезанном старом хвосте
  часть ранних входов не видна, а кошельки, торговавшие только
  рано, не видны вовсе.

Поэтому обрезание старого хвоста делает недоказуемой полноту
множества единиц наблюдения, а не корректность эталона.

## 4. Правило исключения

Рынок исключается из сбора и из всех расчётов, если выполнено
операционное условие:

  запрос limit=10000&offset=10000 возвращает полную страницу
  (10000 строк),

то есть суммарное число сделок по рынку не меньше 20000 и хвост
за стеной существует.

Исключение фиксируется ДО сбора, на этапе preflight. Обход стены
запрещён: не допускаются ни дозагрузка по кошелькам через
?user=, ни сторонние дампы, ни молчаливое усечение. Основание
запрета — дозагрузка по кошелькам достраивает сделки уже
известных кошельков, но не восстанавливает множество кошельков,
и смещение направлено в сторону гипотезы.

Preflight не падает на исключении. Падение допустимо только если
исключено более 20 рынков — это признак смены поведения API,
а не отдельного крупного рынка.

## 5. Единственное срабатывание на замороженном окне

Окно [2026-02-01, 2026-04-28), отбор по gameStartTime.

| Поле | Значение |
| --- | --- |
| conditionId | 0xb1770d16789541de8c805397d2012e1f2e2ff211757098f9df6acbe43540a085 |
| slug | wta-osorio-cristia-2026-02-01 |
| gameStartTime | 2026-02-03 08:00:00Z (unix 1770105600) |
| старейшая достижимая сделка | 2026-01-31 13:00:38Z |
| достижимо предматча | 66.99 ч |
| сделок | не менее 20000 |

Дата в слаге на двое суток раньше gameStartTime; членство в окне
определяется исключительно по gameStartTime, поэтому рынок в окне
законно и исключается не по дате, а по недоказуемой полноте.

## 6. Влияние на контрольные числа

- Перечисление ATP+WTA в окне: 4068. Контрольная полоса
  перечисления 4049..4109.
- Исключено по настоящему правилу: 1.
- Допущено к сбору: 4067.
- Доля исключения: 0.025 % рынков.

Оценка влияния: кошелёк допускается в §5 только при не менее чем
100 матчах, поэтому потеря одного матча сдвигает его статистику
менее чем на сотую долю одного наблюдения.

## 7. Отчётность

В воронку сбора добавляется строка отсева:

  рынки с недоказуемой предматчевой полнотой: N

Состав тиров считается ПОСЛЕ исключения. Предупреждение при
числе сделок свыше 10500 сохраняется как диагностическое и
исключением не является.
