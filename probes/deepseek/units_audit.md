## 3. Ответ: границы +-60 минут в collect_window_v1.py
Границы эталонного окна +-60 минут считаются **в секундах**, НЕ как `ts +- 60*60`
буквально, а как возраст-в-секундах с пределом:
```
106: ETALON_MAX_AGE = 3600      # sec.2: etalon <= 60 minut do starta
858: line0, et_age = market_etalon(rows, gst, clob, clob_set, cond)
859: etalon_ok = (line0 is not None and et_age is not None and et_age <= ETALON_MAX_AGE)
515: return line0, (gst - best_ts)     # age_sec
```
Семантика: принимается последняя сделка рынка с `ts < gst` при `gst - ts <= 3600 сек`
(= 60 минут), т.е. `ts in [gst-60*60, gst)`. Секунды вычитаются из секунд. Верно.

## 4. Единицы таймстемпов на входе (JSON -> масштаб)
- trades: `pull_trades` -> `/trades` raw, сохраняется как есть; `parse_ts` -> int(v)
  БЕЗ /1000. ФАКТ (data/trades_raw_win/*.json): `timestamp: 1770649449` — **секунды**.
- gst: `gameStartTime` из enum API -> parse_ts. ФАКТ (frozen json):
  `gst: 1769929500` — **секунды**.
- Оба входа единообразно в секундах; смешения с миллисекундами при чтении JSON нет.
- Живой книжный коллектор (src/) — отдельная ось в миллисекундах, с историческими
  `trades`/`gameStartTime` не пересекается.
