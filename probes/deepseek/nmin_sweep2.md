**ВАЖНОЕ ОГРАНИЧЕНИЕ (измеренное, не выведенное).** Колонки-значения (`median`, `p90 ATP`,

непустых значений, и все внутри гейта N_min=20 (вне гейта непустых значений 0). Понижение порога
добавляет пары, у которых оценки **нет (null)**. Непустых значений внутри каждой маски:

```

N_min=10 : mask= 30357  non-null spread = 12779

```

Поэтому `median`/`p90` достоверны **только при N_min=20**; для N_min<20 их посчитать из CSV
нельзя — это потребовало бы пересборки пула сделок (запрещено). Колонки, зависящие только от
счётчиков (измеримых всего / среди 81941 / доли по тирам / |M*| / по допущениям), корректно
меняются при всех N_min.

## Шаг 4 — ПРОТИВОРЕЧИЕ: разбор

Единственное множество, где существуют оба значения (обрезанное и сырое) — **N_min=20, D=60, n=12779**.
На нём (точные числа):

```
clipped == 0 : 3894  (30.5%)     clipped < 0 : 0     clipped > 0 : 8885
raw < 0      : 3976  (31.1%)     raw == 0    : 0     raw > 0     : 8803
```

Кросс-таблица (точные множества):

```
raw<0 & clip==0 : 3894   отрицательные, корректно обрезанные в 0
raw<0 & clip>0  :   82   отрицательные, которые НЕ стали нулём
raw>0 & clip==0 :    0   нулей, не объяснённых отрицательным raw, нет
raw>0 & clip>0  : 8803
rows clip != max(raw,0) : 151  (из 12779; здесь clip > max(raw,0), разрыв до 0.0400)
```

**Ответ прямо.** Реального противоречия «вдвое» нет — оно возникло только из-за ошибочной
исторической цифры «1951 / 15.3%».

- Историческое A (нулей после обрезки = 1951, 15.3%) **не воспроизводится**. Фактически на
  множестве 12779 нулей **3894 (30.5%)**. Цифра 1951 не совпадает ни с одним естественным
  множеством: 12779→3894, |M*|(5189)→1743, решающее измеримое (1210)→320. Знаменатель 12779
  историк взял верно (1951/0.153≈12752), но числитель — просто просчёт.
- Историческое B (отрицательных до обрезки = 31.1%) **воспроизводится точно**: raw<0 = 3976 = 31.1%
  на тех же 12779.
- Корректные доли **согласованы между собой**: нулей 30.5% ≈ отрицательных 31.1%, как и обязано быть
  при `clip = max(raw, 0)`. Все 3894 нуля происходят из отрицательного raw (`raw>0 & clip==0` = 0).

**Откуда остаточный разрыв 82.** Из 3976 отрицательных raw 3894 корректно обрезаны в 0, а **82**
сохранили положительное обрезанное значение (`raw<0 & clip>0`). Именно поэтому нулей на 82 меньше,
чем отрицательных. Эти 82 плюс ещё 69 строк (raw>0, но clip≠raw) дают **151** пару, где обрезанная
точечная оценка и колонка `raw` **не являются строгой парой max(·,0)**: на них `clip > max(raw,0)`
(разрыв до 0.04). То есть `spread_cost_point_60` и `spread_cost_point_raw_60` для этих 151 строк
(1.2% от 12779) — не «одна величина до и после обрезки», а слегка разные оценки. Это наблюдаемый
факт из CSV; чинить оценщик не входило в задачу и запрещено.

Итог: две доли посчитаны на одном и том же множестве (12779). Расхождение историка — не в разных
множествах и не в неполной обрезке ко всем парам, а в **неверном числителе 1951**; верное число
нулей 3894 полностью согласуется с 3976 отрицательными.
