Контекст: Поправка 4 вывела prices-history; ретроспективная цена берётся из /trades. Первый замер протухания (n=100) оказался нерепрезентативным: фактически один турнирный день, ITF-перекос. Пул median=22.7 мин усредняет две разные популяции и ничего не описывает.

## 1. Тир определяется префиксом слага
- Тир рынка = префикс слага (например atp, wta, itf и т.д. по инвентарю префиксов), известный ДО матча и не зависящий от исхода.
- Число сделок НЕ используется как критерий стратификации (наблюдается постфактум, открывает степень свободы). Печатается внутри тира как описание.

## 2. Выборка для замера (условие корректности)
- Фиксированная квота на тир, равномерно растянутая по всем 90 дням; не менее 100 матчей на тир.
- В отчёте печатается распределение выборки по датам внутри 90 дней (доказательство растяжки).
- Анкер даты — дата из слага (дата матча), а не номинальный endDate.

## 3. Δ назначается отдельно по каждому тиру
- Δ_strict и Δ_soft назначаются отдельно для каждого тира по распределению протухания этого тира.
- Правило опорной цены и двух порогов — как в DECISIONS_NEEDED (последняя сделка не позже момента разрешения, возраст ≤ Δ; исключённые по протуханию — числом в воронке; GO только при совпадении вывода на обоих порогах, иначе UNDECIDABLE).

## 4. Тиры не сливаются обратно
- В анализе CLV тиры НЕ объединяются в общий пул; отчёт по каждому тиру свой (n, медиана, перцентили, доля gap>30, GO/UNDECIDABLE).
- НО оба тира входят в ОДНУ FDR-семью при q=0.10.
- Разделение тиров сделано ДЛЯ ИЗМЕРЕНИЯ, а не для того, чтобы объявить успехом тот тир, который сработал. Постфактум выбирать «выигравший» тир запрещено.

Пороги / правило GO / K=2.5 / q=0.10 / порядок исходов НЕ меняются. Изменения касаются только стратификации замера протухания и назначения Δ по тирам.
