# Контроль методологии

Это проект, где ошибка в методологии не падает с исключением, а тихо возвращает
красивое неправильное число. Пройди весь чек-лист перед тем, как сказать «готово».

## 1. Единица наблюдения

Единица — **матч**, не сделка. Трейдер, сделавший 40 сделок в одном матче,
даёт ОДНО наблюдение, а не 40.

Красный флаг: `df.groupby("address")["clv"].mean()` без предварительной
агрегации по матчу.

## 2. Ошибки только кластерные

Используй `cluster_mean_se(values, event_ids)` из `pm/stats.py`. Не пиши свой
`np.std(x) / sqrt(n)` — это занизит ошибку в несколько раз.

Два уровня кластеризации обязательны: **матч** и **турнир-день**.
Матчи одного турнирного дня не независимы: один дождь, одно покрытие,
одна новость двигают их вместе. Если две версии дают разный ответ —
берётся КОНСЕРВАТИВНАЯ (большая ошибка), без обсуждения.

Наблюдения внутри одного новостного кластера считаются одним кластером.

## 3. Ранжирование

Только по `posterior_mean` из `shrink()`. Сырой in-sample результат как ключ
сортировки — ошибка. Любой отчёт ОБЯЗАН содержать `shrinkage_fraction`.
Если сжатие близко к 1 — данные ничего не говорят, и это надо сказать вслух.

## 4. Множественные сравнения

`bh_fdr(pvalues, q=0.10)`. Число гипотез = сколько адресов ПРОШЛО фильтр 1,
а не сколько осталось финалистов. Занизить число гипотез — самый тихий
способ получить ложное открытие.

## 5. Решающее правило

```
gross_delta - cost > 2.5 * sqrt(SE_edge^2 + SE_cost^2)
```

СУММА под корнем, не max. K = 2.5, не меняется. Порядок исходов:
UNDECIDABLE проверяется первым, затем GO, затем NO-GO.
Всегда вызывай `decide(...)` из `pm/stats.py`. Не дублируй логику.

## 6. Издержки

Все числа комиссий живут только в `pm/fees.py`. Проверка:

```
grep -rn "0\.07\|0\.05\|0\.04" --include=*.py . | grep -v fees.py | grep -v tests/
```

Должно быть пусто. Если базис комиссии `unknown`, `taker_fee` должен
ПАДАТЬ с `FeeBasisUnresolved`, а не угадывать. Стандартная ошибка издержек
никогда не равна нулю.

## 7. Запрещённые движения

- Подкручивание порога после того, как увидел результат.
- Выбор удобного края вилки издержек.
- Замена кластерной ошибки на обычную «для простоты».
- Отбор трейдеров из лидерборда вместо всей популяции.
- Замалчивание доли выброшенных наблюдений.

Если считаешь какое-то правило неверным — скажи один раз и продолжай
работать по нему. Критерии заморожены до измерения специально.
