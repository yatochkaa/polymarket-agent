# Ограждения безопасности

В маленьком одноразовом проекте обычные веб-чеклисты почти не применимы:
один пользователь, нет публичного ввода. Реальные риски другие.

## 1. Секреты

- Файл конфигурации с секретами никогда не читается вслух, не печатается и
  не копируется в ответ. То же для скриншотов: ключ, попавший в кадр,
  считается утёкшим и подлежит немедленной перегенерации.
- Ни один секрет не попадает в аргументы командной строки: они видны в
  списке процессов и в истории оболочки.
- Перед логированием HTTP-запроса вырезай заголовки авторизации и токены из
  URL. Сырой дамп запросов в файл — типовой канал утечки.
- Проверяй правила игнорирования в системе контроля версий ПЕРЕД созданием
  файла с данными или логом.
- Приватные ключи и платёжные полномочия не нужны аналитике вообще. Если код
  их запрашивает — архитектура неверная.

## 2. Необратимые действия

- Код, способный потратить деньги, отправить письмо, изменить чужие данные
  или удалить их, требует отдельного явного подтверждения и не запускается
  в автоматическом режиме.
- Отсутствие такого модуля — это защита, а не недоделка.
- Реплей и бэктест работают только на исторических файлах.
- Удаление и перезапись — только по явной просьбе владельца, с показанным
  списком того, что будет удалено.

## 3. Аварийный стоп

Стоп считается сработавшим только после ПОВТОРНОЙ проверки состояния.
Код ответа успешного «отменить всё» ничего не гарантирует. Не опирайся на
поля, которые не входят в подписанную/проверяемую часть запроса.

## 4. Лимиты внешних API

- Лимиты каждого эндпоинта выясни и запиши в документ проекта таблицей, с
  датой измерения. Считай запросы на бумаге ПЕРЕД циклом.
- Ограничитель чаще ЗАМЕДЛЯЕТ, чем отказывает: отсутствие 429 не значит, что
  ты в лимите.
- Все сетевые вызовы идут через один клиент проекта с ретраями, бэкоффом и
  ограничением скорости. Свой прямой вызов в обход клиента — ошибка.
- Разные семейства эндпоинтов обычно живут в разных бюджетах: параллельные
  задачи по разным API не конфликтуют, и это стоит проверить, а не
  предполагать.

## 5. Молчаливые отказы

Пустой ответ — это отказ, а не отсутствие данных. Пустой список обязан
порождать явный статус, а не тихо уходить на вход аналитике. Неизвестный
параметр внешний API может проигнорировать, вернув 200.

## 6. Когда не знаешь

Запиши вопрос в `DECISIONS_NEEDED.md` и остановись. Выбрать вариант
самостоятельно и пойти дальше — хуже, чем не сделать ничего.
