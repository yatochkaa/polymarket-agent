# Ограждения безопасности

Обычные веб-чеклисты (XSS, SQL-инъекции, CSRF) здесь почти не применимы:
один пользователь, нет публичного ввода. Реальные риски другие.

## 1. Секреты

- `.env` никогда не читается вслух, не печатается и не копируется в ответ.
- Ни один секрет не попадает в аргументы командной строки — там их видно
  в списке процессов и в истории оболочки.
- Приватный ключ кошелька не нужен ни для одного этапа аналитики.
  Если твой код его запрашивает — архитектура неверная.
- Перед любым логированием HTTP-запроса вырезать заголовки авторизации
  и токены из URL. Сырой дамп запроса в `data/raw_*.jsonl` — частый канал утечки.
- Проверяй `.gitignore` перед созданием любого файла с данными.

## 2. Деньги

Код этого проекта не должен иметь физической возможности поставить ордер.

- Не создавать `pm/broker.py`. Его отсутствие — это защита, а не недоделка.
- Не устанавливать `py-clob-client` (архивный).
- Любой код, способный отправить `POST /order`, требует явной фразы
  `I ACCEPT ORDER PLACEMENT RISK` и не запускается в автоматическом режиме.
- Реплей и бэктест работают только на исторических файлах.

## 3. Аварийный стоп

Ончейн-отмены ордера НЕ СУЩЕСТВУЕТ. Значит единственный честный стоп —
это HTTP DELETE всех открытых ордеров ПЛЮС повторный `get_open_orders`
для проверки, что список пуст.

Запрещено:
- Считать отмену успешной по коду ответа без повторной проверки.
- Опираться на поле `expiration`: оно убрано из подписи EIP-712, хотя
  осталось в теле запроса. Неподписанное поле — не гарантия.
- Проверять операторский `pauseUser` эмпирически. Никогда.

## 4. Лимиты API

Лимиты на 10 секунд на IP:

| Эндпоинт | Лимит |
|---|---|
| `gamma /markets` | 300 |
| `data-api /trades` | 200 |
| `data-api /positions` | 150 |
| `clob /book` | 1500 |
| `clob /prices-history` | 1000 |

Cloudflare чаще ЗАМЕДЛЯЕТ, чем отказывает. Отсутствие 429 не значит,
что ты в лимите. Перед циклом запросов посчитай их число на бумаге.

Все сетевые вызовы идут только через `ReadClient` из `pm/httpc.py`:
там уже есть ретраи, бэкофф и ограничение скорости. Свой `httpx.get`
в обход клиента — ошибка.

## 5. Молчаливые отказы

Пустой ответ — это отказ, а не отсутствие данных. `{"history": []}` и
`{"count": 0, "data": []}` обязаны порождать явный статус, а не пустой
список на входе аналитики. Пользуйся `Envelope.is_empty`.

## 6. Когда не знаешь

Запиши вопрос в `DECISIONS_NEEDED.md` и остановись. Выбрать вариант
самостоятельно и пойти дальше — хуже, чем не сделать ничего.
