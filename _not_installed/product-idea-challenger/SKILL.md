# Product idea challenger

## First inspect

Read the product description, implemented features, current roadmap, and relevant code or issues. Do not propose features that already exist.

## For each serious option

- user and painful problem;
- smallest useful outcome;
- evidence or assumption behind demand;
- reuse versus new surface area;
- implementation and operational cost;
- security, privacy, and support burden;
- measurable success signal;
- recommendation: now, later, validate first, or reject.

## Decision rules

- Prefer one strong next step over a long wishlist.
- Prefer visible reliability and workflow value over decorative AI.
- Prefer deterministic automation before adding an LLM.
- Prefer a manual validation experiment before expensive infrastructure.
- Distinguish portfolio value from customer value.
- Challenge ideas that require ongoing support disproportionate to likely value.
- Identify what not to build.

## Output

Present at most five options, rank them, explain the top trade-off, and end with one concrete next action.
