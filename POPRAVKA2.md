# ПОПРАВКА 2 к предрегистрации Э1 (капчер живого рынка → качение)

Статус: заморожена коммитом 643cdc9f7fa221dfab4cd6b471afe5efd3795dcf
Дата фиксации: 2026-07-31 (Europe/Moscow)

## 0. Причина поправки

Скаут (v8-epoch-life) в четырёх независимых прогонах не нашёл ни одного
длинноживущего (life >= 22 мин) движущегося бинарного крипто-рынка:
long_lived_movers = 0. Всё наблюдаемое движение сосредоточено в коротких
рынках up/down (5m/15m). Длинного движущегося рынка структурно нет,
ширина выборки исчерпана на трёх параллельных активах. Поэтому объём
набирается ВРЕМЕНЕМ ВДОЛЬ ЦЕПОЧКИ (качение на следующий
epoch-рынок), а не шириной по рынкам.

## 1. Метод: качение по параллельным цепочкам

Три параллельные цепочки по активам: btc, eth, sol. Каждая цепочка на
каждом цикле заново выбирает ТЕКУЩИЙ живой короткий up/down рынок своего
актива (epoch <= now < epoch+dur, active & acceptingOrders & not closed,
строго бинарный) и снимает его книгу один раз. Когда рынок
закрывается, следующий цикл автоматически берёт следующий epoch-рынок
той же цепочки (это и есть качение).

Срок/эпоха определяются ТОЛЬКО по слагу вида updown-Nm/Nh-<epoch>, где
epoch = НАЧАЛО окна рынка. По слагу -et время НЕ определяется (дефект
парсера -et признан; -et рынки в выборе времени не участвуют).

## 2. Объём захвата (ФИКСИРУЕТСЯ ЗАРАНЕЕ)

3 цепочки x 120 циклов x 30 с = 360 снимков.
Остановка: СТРОГО ПО ОБЪЁМУ, не по достижению n_div. Это исключает
выборочную остановку (optional stopping): нельзя вести качение до тех
пор, пока n_div не доберётся до 30.

Обоснование объёма: из 360 снимков разогрев 60 с на каждом слоте срезает
около пятой части, ещё часть уходит в no_etalon из-за редких сделок;
останется порядка 250 годных. Порог n_div >= 30 требует от них ~12%
расхождений. При 120 снимках годных было бы 70-90, и порог требовал бы
больше трети — тот же тупик, из-за которого отвергнуты дневные рынки.

## 3. Разогрев (warmup)

Первые 60 с жизни каждого слота (рынка) исключаются: снимки, у которых
capture_ts - epoch_start < 60, помечаются как warmup (Counts.n_warmup) и НЕ
входят в знаменатель (n_aligned/n_divergent).

## 4. Эталон

last_trade = последняя РЕАЛЬНАЯ сделка из /trades (data-api), фильтр по
полю asset = token_id, с timestamp <= времени снимка и в окне 90 с. Если
такой сделки нет — снимок идёт в n_no_etalon (не промах, из знаменателя
исключается). book.last_trade_price из /book НЕ используется как эталон.

## 5. Критерий отбора рынка

- строго бинарный: 2 исхода И 2 clobTokenId И сумма outcomePrices ~ 1
  (допуск 0.02);
- mid в [0.10, 0.90];
- движение mid >= 2 тиков за 5 мин;
- >= 1 реальная сделка за 5 мин;
- порога по ЧАСТОТЕ сделок нет (частотный фильтр отброшен: он срезает
  самые информативные рынки, а устаревание уже гасится правилом 90 с
  no_etalon).

## 6. Решающее правило (без изменений)

Расходящийся снимок: |mid - last_trade| > tick_frac * tick,
tick_frac = 0.5.
Пороги: min_divergent = 30, match_rate_min = 0.90, cross_rate_max = 0.10,
align_window_s = 90.
decide() применяется ОДИН РАЗ к суммарным totals по всем рынкам цепочек:
- n_aligned == 0 -> no_data;
- n_divergent < 30 -> inconclusive (ЧЕСТНЫЙ замороженный исход, НЕ повод
  продолжать качение; более длинный захват возможен лишь как НОВЫЙ
  заранее зафиксированный объём);
- match_mid_rate >= 0.90 и match_last_trade_rate <= 0.10 -> book_mid;
- иначе inconclusive.

Наблюдения внутри цепочки считаются независимыми для вопроса Э1;
кластерные ошибки не применяются.

## 7. Гарантия честности

data/e1_result.json пишется ТОЛЬКО при чистом рабочем дереве
(Поправка 2 закоммичена) и штампуется preregistration_commit = git HEAD.
На грязном дереве результат не пишется.
